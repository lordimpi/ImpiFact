# Spike: Optimus UI para la librería `ui`

Fecha: 17 de noviembre de 2026. Tarea 4 del backlog del frontend (`docs/Arquitectura frontend.md`, §17) y ADR-17.
Pregunta: ¿se puede usar `@openng/optimus-ui` (fork comunitario de PrimeNG) como base de los componentes de `ui`?

## Veredicto

**Sí, con adopción parcial.** Pasa todos los criterios duros (existe, licencia MIT, soporta Angular 22, mantenimiento activo). Se usa para botón, campo de texto, diálogo y esqueleto de carga. La tabla y el paginador se construyen propios sobre HTML semántico porque los de Optimus UI rompen el presupuesto de _bundle_ (§11) y no soportan paginación por cursor. Todo queda envuelto en componentes `ui-*`, así que cambiar de librería después no toca los _features_.

## Decisiones que salen del spike

1. **Preset reducido.** Aura completo pesa unos 145 kB porque trae los _tokens_ de los 80 componentes. `ui` arma su propio preset con la base de Aura y solo los componentes que usa (botón, diálogo, campo de texto, esqueleto), y apunta los _tokens_ semánticos de Optimus a nuestras variables CSS (`--if-*`). Así el modo claro/oscuro lo deciden nuestros _tokens_ y Optimus queda en un solo esquema (`darkModeSelector: 'none'`).
2. **Tabla y paginador propios.** `ui-table` es un `<table>` semántico con cabecera fija, orden por columna con `aria-sort`, filtros y estados; no ordena, filtra ni pagina en el navegador (C5). `ui-paginator` maneja cursor opaco (anterior/siguiente) y números de página cuando el Api da el total. Usan el botón y el esqueleto de Optimus.
3. **CSP.** Optimus en modo _styled_ inyecta etiquetas `<style>` en tiempo de ejecución. Para la CSP sin `unsafe-inline` de §6 hay que pasar el _nonce_ (opción `csp.nonce` de `provideUiTheme`) cuando exista el servidor estático (tarea de despliegue).
4. **Esquema de color.** Optimus inyecta `:root { color-scheme: light }`, que anulaba el modo oscuro por preferencia del sistema. `tokens.css` declara el esquema con `:root:not([data-theme])` y `:root[data-theme=…]`, que ganan en especificidad; la prueba E2E comprueba el fondo de cada tema.
5. **Resultado medido.** Con `provideUiTheme()` en la raíz el inicial queda en 323 kB / 87 kB (antes 265 kB / 74 kB). La vitrina completa (todos los componentes) pesa 181 kB / 37 kB como ruta perezosa. Aviso para las tareas siguientes: cuando una ruta perezosa usa `ui`, el optimizador de _chunks_ del build movió el código compartido a `main` (370 kB en un solo archivo), lo que rompe el presupuesto `anyScript` de 250 kB aunque el inicial total (373 kB) cumpla el de 500 kB. Hay que decidir si ese presupuesto aplica también a `main` antes del primer _feature_.
6. **Seguimiento.** Revisar en cada tarea del backlog si sale una versión nueva; si pasan más de 6 meses sin publicar, reabrir ADR-17. Alternativas evaluadas de respaldo: Angular CDK con componentes propios (ya es dependencia), Spartan/ng (estilo shadcn sobre CDK) y PrimeNG 22, que exige licencia comunitaria con requisitos o comercial por desarrollador.

## Cómo se midió

- Paquetes descargados con `npm pack @openng/optimus-ui@2.0.2 @openng/optimus-ui-themes@2.0.2` fuera del repositorio y leídos sus `LICENSE`.
- Actividad: API pública de GitHub (`repos/openng-org/optimus-ui`, `commits`, `releases`).
- _Bundle_: ruta perezosa de prueba (descartada) que importaba cada componente, con `npm run build`.
